# Durable A/B evidence and owned process teardown

The A/B benchmark previously stopped its Python benchmark before stopping its Go client and exit. A signaling exception at that first step could skip the remaining stops, summary append and profile removal. This repeats the failure pattern observed in the older five-client harness; it is an observer defect, not a measured transport failure.

The new `ArmFinalizer` writes a private, fsynced `workload-outcome.json` before any teardown. It keeps the primary row unchanged, records teardown failures separately, attempts every original child even when an earlier signal or native helper fails, and closes logs and removes owned private profiles on partial setup failures. An emergency catch retains the original outcome and stops the original children even if the observer itself develops an unexpected exception.

Each spawned process is registered immediately with its original `Popen` handle and native process identity. Native journals retain only executable arguments, not environment variables. Benchmark curl children record a private spawn intent before `Popen`, followed by identity registration. Concurrent HTTP workers use separate intent files. The controller reads those journals only after their owning benchmark is reaped, avoiding an append-lock deadlock. Unknown identities or unresolved spawn intents stop the cohort; they are never permission to kill a guessed PID or process group.

Drive cleanup is allowed only after every original Go writer handle is proven reaped. The helper itself makes no Google calls. The guarded external cleanup wrapper must enforce the persisted `writers_stopped` result; parent benchmark exit alone is insufficient. A cleanup error prevents cohort continuation even if a later observation proves all children stopped. Profiles outside the exact owned arm directory are never removed.

The original single-curl journal contract remains compatible. The optional concurrent journal uses one thread-local UUID intent per spawn; the default benchmark path does not install an observer. Any unresolved fixed or UUID intent remains visible to finalization. The Go probe can be marked as a writer conservatively, while warm-up curl is registered as an owned child.

The first helper snapshot, `7614c05`, passed 15 targeted cases. Follow-up `0c4b6bf` passed **31 affected cases in 0.203 seconds**: 18 finalizer cases, seven existing process-journal cases and six concurrent journal cases. Coverage includes denied signals, reused PIDs, unknown native identity, partial setup, manifest-write failure, aggregate helper exceptions, emergency finalization, primary-error retention, child-journal locking, unresolved spawn intents, and out-of-scope profile preservation. Two native macOS tests recorded and reaped only their own public Python sleepers. No network traffic or Google resources were used by these checks.

Separate origin evidence helper `154534d` has twelve passing cases. It retains ten bounded scalar counters for selected bulk requests/completions, failed completions, persistent echo connections/frames, unexpected HTTP and overflow. Final validation requires exactly one chosen bulk request and completion, one echo connection, and one prelude plus every expected echo frame. Extra or failed effects reject immediately; all exact client file/frame receipts remain independently required. This observes the configured process epoch and successful origin processing. It does not count failed TCP dials or prove exactly-once effects across restarts.

These helpers change benchmark ownership and evidence collection. Their implementation tests are not a new live speed, latency or capacity result. Native Linux process teardown remains untested on this Mac, and conditional PID identity checks cannot provide a nonexistent atomic signal-by-creation-time syscall on macOS. Source and policy integration receive separate review before live use; previous interrupted experiments remain unchanged.
