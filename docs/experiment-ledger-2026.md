# Skirk complete experiment ledger, November 15, 2026

This ledger preserves **positive, negative, incomplete, simulated, primitive, and app-level evidence** from prior agents and branches. It is an inventory of available records, not a claim that every possible protocol has been explored. Some archive-only runs lack the exact binary, test conditions, byte verification, quota, or cleanup record; those gaps are explicit.

There are **146 interpreted experiment records**, **282 recognized raw result files** indexed across local worktrees, and **226 sanitized arm observations** imported from available summaries. The index excludes profiles, tokens, config files, browser data and recovery ledgers. Duplicate copied archives remain listed with their worktree; do not count them as independent repetitions.

The strongest forgotten candidate was the **fixed metadata cumulative queue as a persistent small-data lane**. Its substrate results improved text, file rate and unit estimates in both directions. The matched persistent-flow asynchronous ownership test now removes lane-worker processing-ACK blocking while holding the scheduler and carrier equal, and records positive full-TCP results against synchronous slots. The further primary-carrier test stopped on an immutable bulk error, preserving that failure rather than assigning a speed. Final comparisons against actual default mux and clean main remain necessary; none of these results proves a theoretical latency or throughput limit.

## How to compare these records

- `live_full_transport` carries actual TCP/HTTP bytes through Skirk and Drive. `live_api_substrate` carries synthetic slot frames beside a real file; it is not app message RTT. `live_api_primitive` measures Drive operations. `memory_simulation` models local scheduling only.
- Request latency starts when a request actually begins. Scheduled latency includes local queuing from its intended send time. One-way delivery, HTTP TTFB, request completion and request/reply RTT are separate metrics; do not rank them as one number.
- All times and units below retain source definitions. Arm medians/p95s from tiny samples are descriptive. A failed file makes a mixed arm incomplete even when every text message succeeds.
- “Exact zero” means the cited source reports exact generated-prefix/ID cleanup. “Not recorded” is missing evidence, never an assumed pass. Manual eventual cleanup is distinct from sustained automatic garbage collection.
- Historical protocol names collide: May muxv5a/v5b were control/data designs; November `recovery_v5` is an exit-generation extension. They are different protocols.
