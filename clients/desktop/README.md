# Skirk Desktop App

This is the portable Skirk desktop client for Windows, Linux, and macOS. It
imports the same one-line `skirk:` profiles generated by `skirk setup init` and
starts the Go Skirk client sidecar.

Stack:

- Tauri 2
- React
- Go `skirk` sidecar

What it does:

- imports a `client.skirk` or `client.json` file (up to 256 KiB of valid UTF-8),
  or accepts a pasted one-line `skirk:` config;
- stores profiles in app-local or portable data;
- gives each imported profile a stable local client identity, so the same
  copied profile can run on multiple devices at the same time;
- starts/stops the Go Skirk SOCKS and HTTP proxy client;
- supports proxy mode on Windows, Linux, and macOS, plus Windows system proxy,
  Windows VPN, and Linux VPN modes;
- shows proxy addresses, process status, and logs;
- offers an on-demand **Test exit** challenge through the running proxy and
  Drive mailbox; the result is one authenticated round-trip sample, not a
  continuous health signal or a test of arbitrary websites;
- lets each profile choose **Google front** (`www.google.com` TLS SNI) or
  **Direct Google** for reaching the Drive API;
- can bind local proxy listeners to `0.0.0.0` for LAN proxy sharing;
- supports portable Windows, Linux, and macOS app layouts.

It does not require Google login or `gcloud` on the client machine.
The generated profile defaults to Google front. Change **Google access route**
while disconnected when direct Google is available and preferred on your
network; the chosen route is saved with the profile on Windows, Linux, and
macOS.

## macOS Proxy Setup

The macOS app currently supports Proxy mode. **Connect** starts local SOCKS5
and HTTP proxy listeners; it does not route Safari, other browsers, or the whole
Mac automatically.

1. Import a profile and select **Proxy**, then click **Connect**.
2. In your browser's proxy settings, set HTTP and HTTPS to `127.0.0.1:18081`,
   or set SOCKS5 to `127.0.0.1:18080` with remote DNS. Safari uses the proxy
   settings in macOS Network settings. Use the ports shown in Skirk if you
   changed the defaults.
3. Check the local proxy and exit path from Terminal:

   ```bash
   curl --socks5-hostname 127.0.0.1:18080 https://example.com/
   ```

If the command succeeds but your browser still does not load pages, check the
browser's proxy settings. The app does not enable macOS System Proxy or VPN mode
in this release.

## Development

Build the Skirk sidecar first:

```bash
make build
make build-windows
```

Install frontend dependencies:

```bash
cd clients/desktop
npm install
```

Run the app:

```bash
npm run tauri dev
```

## Portable Layouts

Windows ships a zip/folder like:

```text
Skirk.exe
START_HERE.txt
skirk-portable
portable-data/
sidecars/windows/skirk-sidecar.exe
sidecars/windows/skirk-tunnel.exe
```

Linux ships a zip/folder like:

```text
Skirk
START_HERE.txt
skirk-portable
portable-data/
sidecars/linux/skirk
sidecars/linux/skirk-tunnel
```

Portable mode activates when `portable-data/` or `skirk-portable` exists beside the app executable.
Users should open `Skirk.exe` on Windows or `./Skirk` on Linux. The sidecar
binaries are internal runtimes that the desktop app starts and stops.

The app stores:

- `portable-data/config/profiles.json`
- `portable-data/config/settings.json`
- imported profile configs as `portable-data/config/profile-*.skirk` or `profile-*.json`
- logs under `portable-data/logs/`

## Production Notes

Linux desktop mode supports Proxy and VPN modes. Proxy mode exposes SOCKS5 and
HTTP proxy listeners, including trusted-LAN sharing when the imported profile is
configured to bind to `0.0.0.0`. VPN mode uses the bundled `skirk-tunnel`
sing-box sidecar to create a Linux TUN interface, so it must run with root or
`CAP_NET_ADMIN` privileges.

System proxy mode changes the current user's Windows HTTP/HTTPS proxy settings,
stores a backup first, and restores that backup on disconnect or app restart.

VPN mode runs the bundled `skirk-tunnel.exe` sidecar, which is sing-box staged as
a separate TUN runtime in release builds. Creating a Windows TUN adapter requires
Administrator privileges.

For command-line testing without the desktop app:

```powershell
.\skirk-windows-amd64.exe serve-client --config .\client.skirk --listen 127.0.0.1:18080 --http-proxy-listen 127.0.0.1:18081
```

```bash
skirk serve-client --config ./client.skirk --listen 127.0.0.1:18080 --http-proxy-listen 127.0.0.1:18081
```

Add `--client-id my-windows-pc` for a stable CLI identity. The desktop app
passes its saved profile identity automatically.
